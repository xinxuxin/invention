# Backend

FastAPI service for the Data Analysis Agent.

## Development

```bash
python3.11 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
uvicorn app.main:app --reload
```

Or use the backend helper:

```bash
make dev
```

## Current Endpoints

- `GET /health` returns service status for local development and frontend connectivity checks.
- `POST /api/sessions` creates an analysis session and a default `main` branch.
- `GET /api/sessions/{session_id}` returns session metadata and branches.
- `POST /api/sessions/{session_id}/datasets` uploads one or more `.pkl` files, stores originals and initial snapshots, creates initial version nodes, and returns generic object profiles.
- `GET /api/sessions/{session_id}/datasets` lists datasets in a session.
- `GET /api/sessions/{session_id}/datasets/{dataset_id}` returns one dataset profile and current version metadata.

## Python Execution Runtime

`app/runtime/python_executor.py` executes Python snippets generated by the future coding agent. It loads current session snapshots, exposes `datasets`, `data`, `pd`, `np`, `json`, `math`, and `statistics`, captures stdout/stderr/tracebacks, returns JSON-safe previews, and can persist changed datasets as new `VersionNode` snapshots when `mutates_state=True`.

Helper functions available inside executed code:

- `preview(obj)`
- `save_table(name, dataframe_or_records)`
- `save_chart(name, chart_spec)`
- `save_csv(name, dataframe_or_records)`

## Security Note

Loading arbitrary pickle files is unsafe in production because pickle payloads can execute code during deserialization. This take-home assumes trusted demo files. A production implementation should move pickle loading into an isolated worker or sandbox with strict resource limits.

The Python executor is not a secure sandbox. It runs in a child process with timeouts and blocks common network imports/socket calls, but determined malicious code can still abuse Python or local resources. Production execution should happen in an isolated container or worker with OS-level filesystem, network, CPU, memory, and process controls.
